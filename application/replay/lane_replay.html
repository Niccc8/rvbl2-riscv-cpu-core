Every vehicle, one verified transaction

Every decision on this page was made by the chip.
The page only reads its bytes, and checks them.

A multi-lane free-flow toll gantry, run by the RVBL-2 RISC-V chip: it takes RFID tag reads and back-end commands over its UART, vehicle presence and class on its GPIO pins, and decides for every vehicle, sealing each decision with a CRC and a Chaskey-12 authentication tag (ISO/IEC 29192-6). Below is the chip's own transcript, captured at its tx_o pin.

Transcript

P4 charged P5 camera P6 alarm P7 lane closed

Application logic · the emulator link

How ./emu drives the chip

The organisers’ emulator talks to the FPGA top over PCIe and AXI-Lite. Each option writes or reads one register, and each register is one group of the chip’s pins. One command line is one vehicle. Pick one: the command plays step by step, and the right-hand side shows the chip’s own answers, from the emulator preview (every line played on the chip in simulation at 115,200 bps, the way emu plays it).

No decision code here

The chip's column above is decoded from bytes, nothing more. This page never decides a vehicle; the chip's firmware does, running on the RVBL-2 core.

Checked independently

CRC-16 and Chaskey-12 are recomputed in this page with separate code, verified against the Chaskey-12 reference test vectors. A single flipped bit fails both.

The firmware is fingerprinted

On command the chip reads its own ROM, word by word, and reports its size and CRC. It must equal the build's fingerprint.
