# stage4/ — the AWS F2 build

| File | What | Paste into the AWS project? |
| --- | --- | --- |
| `riscv.sv` | **The build file.** RVBL-2 + LaneX firmware as one file, with the `RISCV` shell (MMCM ÷8 → 31.25 MHz, the ASIC's own clock), `Transmitter` and `Receiver`. Generated by `scripts/stage4/gen_riscv_sv.py`; never edit by hand | **Yes** |
| `riscv_15mhz.sv` | Timing backup: identical except MMCM ÷16 → 15.625 MHz. Only if the build log shows the core clock missing timing and the board misbehaves (runbook §6) | Only as a backup |
| `riscv_bufgce_div.sv` | Primitive backup: identical except a BUFGCE_DIV ÷8 instead of the MMCM. Only if the MMCM is refused (runbook §5) | Only as a backup |
| `sim/` | Simulation and lint stand-ins (Xilinx primitives, AWS `sh_ddr`, defines), the system simulator `emu_sys/`, the lint waiver list | No |
| `vendor/` | The organisers' `top.sv`, `emu.c` and AWS's `cl_ports.vh`, unmodified, for the pre-flight gate. **Not in git** (their files) | `top.sv` is theirs, unchanged |

**How to build and check** (details: `docs/stage4/05_RUNBOOK.md`, evidence: `docs/stage4/06_verification.md`):

```bash
python scripts/stage4/gen_riscv_sv.py                     # after any rtl/ or firmware change
python scripts/stage4/gen_riscv_sv.py --clock mmcm_slow --out stage4/riscv_15mhz.sv
python scripts/stage4/gen_riscv_sv.py --clock bufgce_div --out stage4/riscv_bufgce_div.sv
bash scripts/stage4/preflight.sh                          # must end "PREFLIGHT: GO"
```

**Fetch `vendor/`** (once per machine):

```bash
git clone https://github.com/championchip-experience-community/CCX_Malaysia_Edition_Stage_4 /tmp/s4
git clone https://github.com/championchip-experience-community/CCX_Malaysia_Edition_Stage_3 /tmp/s3
mkdir -p stage4/vendor && cp /tmp/s4/src/top.sv /tmp/s3/RVBL-Emulator/src/emu.c stage4/vendor/
cp aws_fpga_example/cl_ports.vh stage4/vendor/            # AWS-provided, as in the guide's project
```

The pre-flight checks their hashes (`top.sv` `0fd7391018a38aee…`, `emu.c` `31e4ca7c3d4c4f08…`).
